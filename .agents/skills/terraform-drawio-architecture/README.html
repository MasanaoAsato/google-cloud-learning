terraform-drawio-architecture 更新手順

このスキルは draw.io 公式のスタイル（AWS Groups / GCP Zones・Paths）とアイコン定義を スナップショットとして同梱している。生成時にネットワークは使わない（図の再現性のため）。 上流の世代交代への追従は、以下の手順で行う。

1. 何がどこにあり、どう更新するか

更新対象置き場所更新方法
AWS Groups の色・grIcon、GCP Paths の線 assets/style-tokens.json の providers.aws.groups と edges_gcp maintenance/sync_upstream.py（手で編集しない）
アイコンカタログ（製品アイコン・Stencil） assets/icon-styles.json scripts/icon_catalog.py --harvest と maintenance/render_stencils.py
スキル独自の規約（寸法、汎用境界、線の6種別、Azure配色） assets/style-tokens.json の残り全部 手で編集してよい（上流が無い＝乖離しない）

2. draw.io 公式パレットへの追従（週次 or 気になったとき）

Python 3.10以降が必要です。scripts/run_python.sh は、環境にある python3またはpythonを選んで実行します。

sh scripts/run_python.sh maintenance/sync_upstream.py          # 乖離チェックのみ（乖離ありなら終了コード2）
sh scripts/run_python.sh maintenance/sync_upstream.py --write  # style-tokens.json を上流へ追従
sh scripts/run_python.sh scripts/self_test.py                  # 回帰テスト
# 最後にサンプル図を再生成してプレビューを目視する（色の世代交代は目で確認）

出典URLと最終検証日は style-tokens.json の upstream にある。 可読性のための意図的な逸脱（例: VPCラベル色）は providers.aws.group_overrides に 置いてあり、sync はここを触らない。

3. 自動化（推奨・独立リポジトリ化後）

maintenance/ci-sync-drawio-upstream.yml を独立リポジトリの .github/workflows/ へ置くと、週1回 sync が走り、 乖離があった週だけ PR が自動で立つ。 self_test 通過済みなので、差分を見てマージするだけで追従が完了する。 利用者側への配布は skills.sh の npx skills update が担う。

4. アイコンが足りないとき

# カタログに無いサービス: Draw.io で実際に置いた図から取り込む
sh scripts/run_python.sh scripts/icon_catalog.py --harvest <その.drawio>

# SVG書き出しが「no pre-rendered SVG for ...」で失敗: 事前レンダリングを追加
sh scripts/run_python.sh maintenance/render_stencils.py            # alias から到達できる全シェイプ
sh scripts/run_python.sh maintenance/render_stencils.py gcp2/users # 特定シェイプのみ

5. やってはいけないこと

  • providers.aws.groups / edges_gcp を手で編集する（sync が上書きする。逸脱は group_overrides へ）
  • 生成スクリプトに上流フェッチを組み込む（オフラインで壊れ、同じ仕様から違う図が出る）
  • style 文字列を推測で書く（draw.io では空の四角になる。必ず harvest か sync を通す）
公開・パッケージ前のチェックリスト: find . -name __pycache__ -exec rm -rf {} + で削除し、 個人情報・社内情報が無いことを確認する（メール、社員ID、絶対パス、プロジェクトID）。
